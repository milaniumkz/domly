# Проверка технической панели

Тестовые объекты создаются отдельно от production. Интеграционные проверки технического центра создают собственную временную PostgreSQL, применяют настоящую схему и удаляют БД после проверки.

## Автоматические проверки

```sh
cd backend
npm ci
npm run build
DOMLY_INTEGRATION_DATABASE_URL=postgres://.../domly_test node --test dist/tests/*.test.js
```

Технические интеграционные тесты проверяют отдельный успешный/ошибочный вход, CSRF/Origin, отсутствие доступа по JWT админки, ограничения пользователя и PII, отдельные события повторов, HMAC, отсутствие смешивания хронологии, допустимость GPS, отказ/ручную проверку/принятие изображений, точную связь файлов и события, серверный доступ к оригиналам, checksum и аудит, подстановку чужого UUID, закрытие проблемы только с результатом проверки, свой центр уведомлений, дедупликацию, запрещённые push-endpoints, незавершённое обращение, worker heartbeat, блокировку и отзыв JWT, временный пароль, смену технического пароля и logout. Отказы провайдеров и хранилища вводятся как контролируемые сбои тестовых зависимостей, а не как демонстрационные production-метрики.

Локальный полный результат: **155 backend-проверок, все пройдены, пропусков нет**. Flutter: **88 проверок** (80 localization/models/services и 8 app/utils), все пройдены. Анализ Flutter — без errors; в проекте остаются существующие warnings/info, поэтому штатный анализ использует `--no-fatal-infos --no-fatal-warnings`.

## Браузер и реальные файлы

В отдельной тестовой БД и реальном локальном MinIO проверены: обязательная первая смена пароля; все 11 разделов; превью изображения; скачивание исходных байтов; переход к точной хронологии; установка Service Worker с scope только технической панели; мобильная ширина 393 px; завершение сеанса. Конкретные запросы, снимок экрана и отчёт сохраняются как артефакты проверки, без паролей и пользовательских production-файлов.

Начальный GET /me до входа штатно возвращает 401 — это не отказ приложения. Web Push при закрытой вкладке требует отдельной проверки на устройстве с разрешёнными уведомлениями; регистрация Service Worker сама по себе не доказывает доставку. Дополнительно выполнено восстановление SQL-dump в отдельную PostgreSQL: схема и число строк пяти таблиц совпали. В реальном MinIO проверены отказ анонимного чтения (403), отсутствие публичной политики и совпадение SHA-256 исходного и восстановленного объекта.

Нагрузочное тестирование, внешний WORM и антивирусная экспертиза PDF не выполнялись.

После развёртывания сюда добавляется проверенный commit, результат GitHub Actions, проверка фактической версии и доступности панели. Нельзя считать установленной только версию в GitHub: проверяется ответ сервера/образа.
