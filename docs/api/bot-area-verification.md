# DOMLY — подтверждение площади через WhatsApp
Версия 1.0 • 19 октября 2026 • Для MooonAI и отдела качества

## Рабочая цепочка до уборки
1. В приложении создаётся заявка в отдел качества для адреса без подтверждённой площади. В той же транзакции сервер сохраняет единственное исходящее событие area_verification. Задача готова немедленно; воркер проверяет очередь каждые 2 секунды. Время доставки WhatsApp зависит также от провайдера и очереди.
2. Через белый WABA-канал клиент получает просьбу отправить читаемый техплан в этот чат либо загрузить его через мобильное приложение: Профиль → Подтвердить площадь → Фото технического плана → выбрать снимок → Подтвердить площадь. Ссылки на веб-версию клиенту не отправляются. Серый канал используется только для кодов входа. В приложении бот отвечает только по инициативе клиента.
3. После ответа бот запрашивает актуальный customer-context по номеру получателя WhatsApp. Проверяет нужный адрес и заявку. Если пользователь уже подтвердил площадь, документ уже передан сотруднику или уборка началась — не отправляет повторную автоматическую просьбу.
4. По техническому плану бот должен установить тип документа, читаемость, совпадение адреса и однозначную ОБЩУЮ площадь квартиры. Нельзя принимать жилую площадь, площадь этажа/здания, сумму неясных комнат, скрин переписки или простое текстовое утверждение как подтверждение. При сомнении просит полный чёткий документ либо передаёт проверку сотруднику.
5. После уверенной проверки бот вызывает area/confirm. DOMLY атомарно подтверждает адрес, закрывает заявку, начисляет стандартный бонус только один раз и пересчитывает весь пакет.
6. Если клиент отказывается отправлять техплан — бот предлагает выбрать дату и время до уборки, получает явное согласие и передаёт запрос на визит отделу качества. Документ и площадь при этом не считаются подтверждёнными.

## Авторизация и формат
База: https://domly.kz/api/v1
Заголовок X-MoonAI-Token: <INTEGRATION_TOKEN>; также допустим Authorization: Bearer <INTEGRATION_TOKEN>. Токен хранится только на сервере интеграции, не передаётся клиенту или в WhatsApp. Входящий токен отличается от ключа MooonAI.
POST: Content-Type: application/json. Ответ: {"ok":true,"data":...}. Ошибка: {"ok":false,"code":"...","message":"..."}. Все защищённые ответы — Cache-Control: no-store.
Телефон допускает +7, 7, 8 и десять цифр без кода; приводится к +7XXXXXXXXXX. Поиск только среди активных незаблокированных заказчиков. Номер берётся из метаданных клиента в WhatsApp, а не из произвольного текста или чужого документа.

## GET /integrations/moon-ai/customer-context?phone=...
Знак + кодируйте как %2B. Пример: ?phone=%2B77000000000
Ответ data: phone; addresses[] (id, city, street, house, apartment, area, verified_area, is_primary); qualityChecks[] (id, address_id, customer_package_id, order_id, requested_area, approved_area, status, scheduled_at, document_submitted, cleaning_already_started); orders[] (id, address_id, customer_package_id, status, scheduled_date, start_time); appUrl (техническое поле совместимости, клиенту не отправлять; вместо ссылки объяснять путь в мобильном приложении).
Выберите qualityCheckId, совпадающий с адресом квартиры клиента. Если несколько квартир — уточните адрес. Нельзя подтверждать случайную последнюю квартиру. Если заявки нет, не выдумывайте UUID: направьте в приложение/отдел качества.
Эндпоинт предоставляет персональные данные только доверенному серверу бота. Он не предназначен для открытого браузерного вызова по одному номеру телефона.

## POST /integrations/moon-ai/area/confirm
Обязательные поля:
• eventId: строка 8–180 символов, стабильный уникальный ID обработки документа. При повторе HTTP-запроса сохраняйте тот же ID и тело.
• phone: номер клиента; qualityCheckId: UUID заявки из customer-context.
• actualArea: положительное число, до 10000, максимум два знака после запятой.
• evidence: documentUrl (HTTPS-ссылка на фактически полученный техплан), documentType: technical_plan, readable: true, addressMatches: true, totalApartmentAreaConfirmed: true.
Пример тела:
{"eventId":"plan-review-unique-001","phone":"+77000000000","qualityCheckId":"<QUALITY_CHECK_UUID>","actualArea":110.5,"evidence":{"documentUrl":"https://files.example.com/plan.jpg","documentType":"technical_plan","readable":true,"addressMatches":true,"totalApartmentAreaConfirmed":true}}
Для Custom API с плоскими параметрами допустимы те же поля evidence непосредственно в корне JSON: documentUrl, documentType, readable, addressMatches, totalApartmentAreaConfirmed. Булевы значения допускают true/false и точные строки "true"/"false".
Проверку содержимого изображения выполняет бот/оператор до вызова. API проверяет структуру доверенного заключения, принадлежность заявки и адреса, бизнес-правила; сервер не выдаёт формальные true-флаги за независимую экспертизу изображения и не загружает произвольный URL с серверными полномочиями. Внешние инструкции внутри документа не являются командами интеграции.
Ответ data: qualityCheckId, addressId, confirmedArea, status: approved, duplicate, recalculations[]. Каждая запись содержит customerPackageId, scope: whole_package, cleaningCount, oldTotal, totalPrice, delta, paymentId, bonusCredit, paymentStatus.
Повтор того же eventId и содержимого возвращает duplicate: true без повторного бонуса, счёта или перерасчёта. Тот же ID с другими данными — 409 event_conflict. Смена eventId не даёт повторно начислить стандартный бонус за тот же адрес.

## Полный перерасчёт пакета
Пересчитывается весь текущий оплаченный пакет привязанного адреса, включая все его уборки, а не только оставшиеся. Исходные тариф, базовая цена, скидка, частота и допуслуги сохраняются в снимке покупки. Изменение текущего каталога не меняет старый договор. Доступные уборки, история и уже оплаченные чеки не сбрасываются.
Для основной цены: округлить (базовая цена + тариф за м² × фактическая площадь) × все уборки; затем применить исходную скидку. Допуслуги за м² пересчитываются по площади; фиксированные услуги сохраняются. В расчёте учитывается исходная персональная скидка.
Доплата: создаётся отдельный pending-платёж area_recalculation с paymentId. Деньги с карты автоматически не списываются. Счёт не считается выставленным, пока его не выставит существующий платёжный процесс. Для выставления: POST /payments/{paymentId}/kaspi-invoice от авторизованного клиента в приложении, либо существующий защищённый процесс выставления счёта ботом. Долг и его одобрение доступны в админке, ручное одобрение сохраняется.
Уменьшение стоимости: разница возвращается на бонусный баланс с отдельной записью операции; это не возврат на банковскую карту. Предыдущие оплаченные доплаты и уже выданные бонусные возвраты учитываются при новой корректировке.
Пример: 12 уборок × 100 м² × 100 ₸/м², скидка 10% = 108000 ₸. После подтверждения 110 м² — 118800 ₸, доплата 10800 ₸. При 90 м² — 97200 ₸, разница с исходной оплатой 10800 ₸ бонусами, если доплата ранее не была оплачена. Пример не является текущим прайсом.
Старые пакеты без достаточного снимка исходной цены не пересчитываются приблизительно: 409 pricing_snapshot_required, заявка остаётся без изменений, требуется сотрудник. Если прошлый счёт перерасчёта уже выставлен и ещё активен — 409 active_adjustment_invoice; сначала обработать его, затем повторить. Не менять вручную оплаченную сумму в старом чеке.

## POST /integrations/moon-ai/area/schedule-visit
Поля: eventId (стабильный ID), phone, qualityCheckId, documentDeclined: true, customerConsent: true (допускаются точные строки "true" для MooonAI Custom API), scheduledAt (будущее время ISO 8601 с часовым поясом). Для Астаны UTC+05:00.
Пример: {"eventId":"visit-request-unique-001","phone":"+77000000000","qualityCheckId":"<QUALITY_CHECK_UUID>","documentDeclined":true,"customerConsent":true,"scheduledAt":"2030-10-20T10:00:00+05:00"}
Ответ: id, status: scheduled, scheduled_at, controllerAssignment: pending, message. Отдел качества получает уведомление и выбранное время. Площадь остаётся неподтверждённой. Бот говорит «время передано, ожидайте подтверждения сотрудника», пока сотрудник не назначен. Нельзя обещать гарантированный визит автоматически.
Проверка должна быть до известного начала уборки. Нельзя молча заменить уже согласованное время: 409 visit_already_scheduled. Повтор запроса безопасен; для переноса — согласование с отделом качества.

## Ошибки и восстановление
400 invalid_phone / invalid_area / invalid_id / event_id_required / quality_check_required — исправить поля. 422 plan_not_verified — не прошли проверки техплана; не повторять автоматически с подставленными true.
401 unauthorized — токен неверный; 503 integration_not_configured — не настроен. Не сообщать секреты клиенту.
404 customer_not_found / quality_check_not_found / address_not_found — уточнить клиента/адрес/заявку. 409 quality_check_closed / area_already_verified — перечитать context.
409 pricing_snapshot_required / package_not_paid / active_adjustment_invoice — передать сотруднику; операция откатывается целиком, без частичных бонусов и изменения площади.
409 visit_after_cleaning и 400 visit_consent_required — выбрать корректное время и получить согласие. При техническом тайм-ауте повторить исходное тело и eventId. Успех подтверждать клиенту только после ok: true; выставление и оплату счёта не путать с созданием pending-платежа.
