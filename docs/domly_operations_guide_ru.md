# DOMLY: инструкция по системе и админ-панели

Актуально для текущего состояния проекта в репозитории `DOMLY`.

## 1. Назначение системы

DOMLY состоит из трех поверхностей:

1. `DOMLY` для клиентов
2. `DOMLY Pro` для уборщиц
3. `DOMLY Admin Web` для администраторов, менеджеров и суперадминистраторов

Система покрывает:

- авторизацию
- создание и покупку пакетов уборок
- выбор дат и слотов
- назначение уборщиц
- контроль статусов заказа
- верификацию уборщиц
- обучение через видео
- реферальную систему
- проверку площади квартиры
- жалобы, отзывы, чек-листы и выплаты

## 3. Роли и доступы

### 3.1 Клиент

Клиент может:

- войти по номеру телефона
- заполнить профиль квартиры
- подтвердить площадь
- выбрать пакет
- выбрать даты уборок
- заказать разовые услуги и доп. услуги
- смотреть историю заказов
- общаться в чате по заказу
- оставлять жалобы и отзывы
- смотреть полезные видео
- участвовать в реферальной программе

### 3.2 Уборщица

Уборщица может:

- войти по номеру телефона
- заполнить профиль
- пройти верификацию
- видеть назначенные заказы
- работать с календарем
- проходить обучение
- работать с чек-листом заказа
- смотреть бонусы и доход
- использовать чат по заказам

### 3.3 Администратор

Администратор входит по email и паролю.

Доступ в админку определяется custom claims:

- `superAdmin`
- `admin`
- `manager`

Реальные ограничения по коду:

- `Суперадмин`: полный доступ
- `Администратор`: практически полный доступ
- `Менеджер`: не может редактировать политики и не может запускать выплаты

## 5. Авторизация

### 5.1 Клиенты и уборщицы

Используется вход по номеру телефона через OTP-поток.

Важно для операционной команды:

- в текущей логике код может отправляться через внешний канал
- если внешний канал не настроен или недоступен, система может работать в fallback-режиме
- в fallback-режиме код может показываться на экране

Если пользователь говорит: «код не приходит», нужно проверить:

1. правильность номера телефона
2. не заблокирован ли внешний провайдер доставки
3. не появился ли код на самом экране
4. нет ли ошибки в Cloud Functions `requestOtp` или `signInWithOtp`

### 5.2 Админка

Админка использует:

- email
- password

После входа система обновляет токен и проверяет claims.

Если у аккаунта нет нужных claims, вход в админку будет отклонен.

## 7. Жизненный цикл заказа

Системные статусы заказа:

- `pending_payment`
- `pending_assignment`
- `assigned`
- `in_progress`
- `completed`
- `disputed`
- `canceled`

Разрешенные переходы:

1. `pending_payment` -> `pending_assignment` или `canceled`
2. `pending_assignment` -> `assigned` или `canceled`
3. `assigned` -> `in_progress` или `canceled`
4. `in_progress` -> `completed` или `disputed`
5. `disputed` -> `completed` или `canceled`

## 8. Как работает клиентская часть

### 8.1 Главная логика клиента

На стороне клиента доступны:

- главная
- пакеты
- калькулятор
- профиль
- история заказов
- рефералы и бонусы
- подтверждение площади
- видео

### 8.2 Профиль клиента

Обязательные поля профиля:

- `Мой адрес`
- `Площадь квартиры`
- `Телефон`

Дополнительные поля:

- `ФИО`
- `Пол`

Реферальный блок:

- `Кто вас пригласил`

Поля адреса, которые реально сохраняются:

- `residentialComplex`
- `entrance`
- `apartment`
- `area`
- `name`
- `gender`

### 8.3 Пакеты

В текущей системе предусмотрены пакеты:

- `Разовый пакет`
- `Два раза в месяц`
- `4 раза в месяц`
- `8 раз в месяц`
- `Квартальный пакет`
- `Генеральная уборка`
- `Уборка после ремонта`

Логика:

- базовая стоимость зависит от площади квартиры
- месячные пакеты считают стоимость по числу уборок
- квартальный пакет считает `3 месяца` и применяет скидку `10%`
- доп. услуги в калькуляторе считаются как разовая добавка и не умножаются на количество уборок

### 8.4 Выбор дат по подписке

После покупки подписки клиент выбирает доступные даты.

Система:

- рассчитывает доступные слоты через backend
- не дает выбрать слот при конфликте
- не дает выбрать слот вне возможностей уборщицы

Важно:

- в интерфейсе `Осталось уборок` должно показывать именно доступные к бронированию уборки
- уже выбранные, но еще не выполненные даты тоже уменьшают доступный остаток

### 8.5 Подтверждение площади

Экран подтверждения площади:

- клиент вводит фактическую площадь
- при необходимости прикрепляет фото техплана
- система отправляет данные в backend

Если площадь совпадает с правилами допуска:

- площадь подтверждается
- клиент может получить бонус

Если есть расхождение:

- кейс попадает в `Проверка площади` в админке

## 10. Как работает админ-панель

## 10.1 Общая структура

Верхняя часть админки:

- название панели
- роль текущего сотрудника
- поле поиска по текущему разделу
- кнопка `Сохранить вид`
- кнопка выхода

Слева находится меню разделов.

## 10.2 Разделы админки

### 10.2.1 Дашборд

Нужен для:

- просмотра основных показателей
- быстрых переходов в проблемные зоны
- оценки загрузки и узких мест

### 10.2.2 Заказы

Нужен для:

- просмотра всех заказов
- контроля статусов
- ручных действий по заказу
- назначения и переназначения

Операционные задачи:

1. найти заказ
2. проверить статус
3. убедиться, что оплата проведена
4. при необходимости назначить или снять уборщицу
5. довести статус до фактического состояния

### 10.2.3 Жалобы

Нужен для:

- работы с претензиями
- компенсациями
- возвратами

Рекомендуемый процесс:

1. открыть жалобу
2. проверить связанный заказ
3. определить, нужна ли компенсация
4. зафиксировать решение

### 10.2.4 Платежи

Нужен для:

- контроля статусов оплат
- проверки, оплачен ли заказ
- ручной сверки спорных кейсов

### 10.2.5 Выплаты

Нужен для:

- контроля начислений уборщицам
- запуска weekly payout

Важно:

- менеджер не должен иметь права запуска выплат
- этот раздел критичен для контроля перед ручными финансовыми действиями

### 10.2.6 Отзывы

Нужен для:

- просмотра оценок клиентов
- чтения текстов отзывов
- просмотра фото

### 10.2.7 Чек-листы

Нужен для:

- контроля доп. услуг
- контроля завершения уборки

### 10.2.8 Уборщицы

- просмотра профилей уборщиц

- проверки статуса верификации

### 10.2.9 Кластеры

## 11. Операционная логика по пакетам и уборкам

### 11.1 Остаток уборок

Важно различать:

- общее количество включенных уборок
- уже использованные уборки
- уже назначенные будущие уборки

Для оператора корректный остаток для клиента — это:

`включено - использовано - уже назначено`

То есть если в пакете `8` уборок и клиент уже выбрал `2` даты, в интерфейсе должно показываться `6`.

### 11.2 Заморозка пакета

В профиле клиента есть действие `Заморозить пакет`.

Правило:

- заморозка доступна только для месячных и квартальных пакетов

### 11.3 Создание своего пакета

Через калькулятор клиент может собрать кастомный расчет.

Важно:

- итог зависит от площади
- доп. услуги считаются как разовые, а не множатся на число уборок

## 12. Чат, жалобы, отзывы, видео

### 12.1 Чат

Чат привязан к заказу.

Участники:

- клиент
- назначенная уборщица

Чат нельзя использовать по заказу, где уборщица еще не назначена.

### 12.2 Жалоба

Жалоба открывается по конкретному заказу.

Используется для:

- фиксации претензии
- эскалации спорной уборки

### 12.3 Отзыв

Отзыв открывается по заказу после выполнения.

Используется для:

- оценки
- текста
- фото

### 12.4 Видео

Клиентские видео:

- инструкции по сервису
- объяснение услуг

Видео уборщиц:

- обучение
- обязательные материалы
- стандарты работы

## 13. Повседневный сценарий работы администратора

### 13.1 Ежедневно утром

1. открыть `Дашборд`
2. проверить проблемные KPI
3. открыть `Заказы`
4. проверить `pending_assignment`
5. проверить `Верификация`
6. проверить `Проверка площади`
7. проверить `Жалобы`

### 13.2 В течение дня

1. контролировать оплаты
2. контролировать назначение уборщиц
3. проверять конфликты слотов
4. отвечать на спорные кейсы
5. следить за закрытием заказов

### 13.3 Еженедельно

1. проверять `Выплаты`
2. проверять `Отзывы`
3. обновлять `Видео и обучение`, если нужно
4. актуализировать `Инфо-контент`
5. проверять `Пакеты` и `Политики`

## 14. Типовые инструкции для нового сотрудника

### 14.1 Если клиент не может заказать уборку

Проверить:

1. заполнен ли адрес
2. заполнена ли площадь
3. подтверждена ли площадь, если это требуется
4. есть ли активный пакет
5. есть ли доступные даты
6. не исчерпан ли остаток уборок

### 14.2 Если уборщица не может получать заказы

Проверить:

1. заполнен ли профиль
2. загружены ли документы
3. одобрена ли верификация
4. есть ли привязка к кластеру
5. не перегружен ли ее день по расписанию

### 14.3 Если не видно видео

Проверить:

1. `isActive`
2. `audienceType`
3. заполнена ли `videoUrl`
4. нужна ли аудитория `Обе роли`

### 14.4 Если не сохраняется профиль

Проверить:

1. есть ли обязательные поля
2. нет ли ошибки прав
3. проходит ли запись через backend callable

## 15. Ограничения и важные правила

- нельзя вручную считать остаток уборок без учета уже назначенных дат
- нельзя считать доп. услуги как множитель по всем уборкам, если это разовая услуга
- нельзя публиковать видео не той аудитории
- нельзя вручную менять критические поля клиента или уборщицы в обход backend, если они защищены правилами
- выплаты должен запускать только сотрудник с нужными правами
- при споре по площади кейс нужно закрывать через админку, а не просто менять цифры без фиксации

## 17. Рекомендуемый порядок обучения нового человека

1. Дать доступ в нужную поверхность
2. Показать вход и ролевые ограничения
3. Пройти клиентский путь:
   - профиль
   - площадь
   - пакет
   - даты
   - заказ
4. Пройти путь уборщицы:
   - профиль
   - верификация
   - календарь
   - чек-лист
5. Пройти всю админку сверху вниз
6. Отдельно обучить:
   - верификации
   - жалобам
   - проверке площади
   - пакетам
   - видео
   - политикам
7. Дать доступ к этой инструкции как к основной рабочей базе

## 18. Краткий вывод

Если человеку нужно быстро понять систему, он должен запомнить 5 вещей:

1. Клиент живет вокруг пакетов, площади, дат и заказа
2. Уборщица живет вокруг верификации, календаря, чек-листа и обучения
3. Админка управляет заказами, людьми, контентом, пакетами и правилами
4. Важнейшие спорные зоны: остатки уборок, верификация, площадь, жалобы, аудитория видео
5. Все критические изменения надо делать через предусмотренные разделы и backend-логику, а не ручными хаками по данным
