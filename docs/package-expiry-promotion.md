# Временная отмена сгорания пакетов

Включение выполняется после деплоя через `server-ops.yml`, действие `package-expiry-promotion-start` из `main`. Операция сначала включает защиту, затем создаёт личное уведомление каждому существующему неудалённому аккаунту всех ролей, включая пользователей без пакетов. Уведомления сохраняются в приложении и попадают в штатную очередь push. Устройства без разрешения или рабочего push-токена получают только запись в приложении. Повторный запуск не создаёт дубликаты.

Текст уведомления: «Если вы получили уведомление о скором сгорании пакета, не переживайте — мы сделали для вас исключение. Оставшиеся уборки в вашем пакете в ближайшее время не сгорят. Постарайтесь использовать их в срок».

Защита действует для активных месячных и квартальных пакетов, новых покупок, просмотра календаря, бронирования приложением и ботом, а также фонового списания. Уже использованные и ранее сгоревшие уборки не восстанавливаются. Предупреждения об истечении срока не создаются и не доставляются во время акции. Для старых приложений дата окончания в `/packages/my` временно не возвращается, чтобы календарь не скрывал допустимые даты.

По отдельному указанию владельца действие `package-expiry-promotion-stop` закрывает паузу. При следующем пересчёте срок каждого затронутого периода продлевается на время паузы, один раз; новый пакет получает продление только за время после его оплаты. Это предотвращает мгновенное списание за прошедшую акцию. Сообщение об окончании само не рассылается.

Не редактируйте даты пакетов вручную. История интервалов находится в `app_settings.packageExpiryPromotion`, применённые продления — в `customer_packages.expiry_pause_offsets`. Маркер рассылки `packageExpiryPromotionAnnouncement_20261128` не позволяет старой операции повторно включить уже законченную акцию. Для новой акции нужен новый согласованный маркер рассылки.
