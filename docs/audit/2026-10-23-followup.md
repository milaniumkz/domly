# Продолжение аудита Domly — 23 октября 2026

Работа после опубликованного релиза `5048de38528b716b7eff487e9fc1ba6aa14e0f2c` ведётся отдельно в `codex/audit-followup-20261023`. Новые изменения не опубликованы на рабочем сервере.

## Воспроизведённые дефекты

1. `BonusService` открывал транзакцию, но выполнял запросы через пул, вне её соединения. Ошибка вставки истории оставляла изменённый баланс. В конкурентном воспроизведении проходили 9 списаний по 80 при балансе 100 вместо одной операции.
2. Создание бонусного платежа фиксировало статус `paid` до успешного списания. При отказе записи истории оставался ложный оплаченный платёж.
3. У сохранённого заказа `pending_payment` без записи платежа отсутствовала кнопка повторной оплаты.
4. Постоянные события realtime откладывали обновление интерфейса: каждый новый event сбрасывал таймер. В тесте во время потока обновлений не было.
5. Счётчик непрочитанных в меню скачивал полную историю уведомлений. У тестового клинера 3430 записей занимали около 2 МБ; список уведомлений загружал её отдельно.

## Изменения

Баланс и история бонусов используют одно соединение и одну транзакцию. Создание платежа, списание бонусов и изменение суммы заказа фиксируются вместе. Проверка доступного баланса защищена блокировкой строки. Проценты и финансовые правила не менялись.

Неоплаченный заказ без созданного счёта предлагает повторить оплату. Активный счёт и оплаченный заказ по-прежнему не предлагают дублирующую оплату.

Realtime объединяет события в ограниченном временном окне, а не ждёт остановки потока. Для счётчика используется существующий `/notifications/unread-count`; полная история сохраняется в разделе уведомлений. Ответ от предыдущего аккаунта не применяется после смены пользователя.

## Проверки и границы

Регрессии: `backend/src/tests/bonus-atomicity.test.ts`, `test/services/order_payment_retry_test.dart`, `test/services/realtime_updates_test.dart`, `test/services/notification_count_stream_test.dart`.

Браузерный сценарий `test/e2e/payment_atomicity.cjs` запускается только в отдельной БД `domly_audit_20261023`. Он инъецирует отказ записи истории для одного синтетического пользователя: HTTP 500, баланс 10000 сохранён, платежей нет; повторная оплата через видимые кнопки — HTTP 200, списано 2000, баланс 8000, платёж `paid`, заказ `pending_assignment`. Скриншоты подтверждают ошибку и успешный повтор.

Для замеров realtime стенд должен обслуживать приложение и SSE на одном локальном origin. Подмена HTTPS-страницы с обращением к другому локальному origin блокировала соединение в тестовом браузере, и прежние замеры фактически измеряли fallback polling. Подключение потока проверяется отдельно по HTTP 200, порог 2 секунды не ослабляется.

Атомарность всей последующей обработки `applyPaidPayment`, внешние банковские отказы, все сценарии отмены/возврата и полная смешанная нагрузка на 1000 пользователей остаются отдельными проверками. Эти исправления не являются заявлением о завершении всего аудита.
