# Онлайн-оплата BCC

Источник протокола: [официальная документация BCC e-Commerce WEBVIEW](https://documenter.getpostman.com/view/23274245/2s7YYo95nr).
Проверено 14 октября 2026 года. Legacy Firebase Functions в оплате не используются.

## Режимы

- `BCC_MODE=disabled`: онлайн-оплата недоступна.
- `BCC_MODE=test`: публичный стенд BCC, терминал `88888881`, merchant `00000001`, MAC-ключ `6BB0AC02E47BDF73D98FEB777F3B5294` из документации. Интерфейс явно отмечает тестовый режим. Бонусы не используются, результат теста не активирует реальные пакеты и не отправляет уборщицу.
- `BCC_MODE=live`: реквизиты Domly из банка — `BCC_MERCHANT_ID`, `BCC_TERMINAL_ID`, `BCC_PRIVATE_KEY` (собранный HEX MAC-ключ), `BCC_MERCHANT_NAME`, `BCC_NOTIFY_URL`, `BCC_RETURN_URL`, `BCC_NOTIFY_USER`, `BCC_NOTIFY_PASSWORD`. Публичные тестовые терминалы запрещены. Ключи хранятся в защищённой конфигурации сервера. `BCC_PUBLIC_KEY` не требуется для HMAC-SHA1.

Тестовый режим включается вручную workflow **Configure BCC sandbox** из проверенного `main`. Перед изменением конфигурации создаётся резервная копия. Реквизиты боевого банка и Kaspi сохраняются.

## Поток платежа

Бэкенд выдаёт подписанную форму, браузер или WebView открывает платёжную страницу BCC. Данные карты вводятся только на странице банка. Подпись — HMAC-SHA1 по последовательности полей из документации; формат суммы — две десятичные цифры, валюта — `398`, время — UTC. Номер банковской попытки выделяется отдельной последовательностью PostgreSQL. Повторное открытие свежей сессии использует существующий номер.

Уведомление `POST /api/v1/payments/bcc/webhook` и возврат `/api/v1/payments/bcc/return` запускают независимую проверку `TRTYPE=90` непосредственно у банка. Присланное клиентом `paid` или `RC=00` само по себе не подтверждает покупку. Проверяются банковские номер, терминал, сумма и валюта. Для live требуется зарегистрировать адрес уведомлений и Basic Auth в BCC: официальный раздел «НАСТРОЙКИ УВЕДОМЛЕНИЙ», `itsup-ecom@bcc.kz`. Уведомление должно иметь явный порт `:443`.

Ручное одобрение в админке сохранено. Банковский возврат не отмечается успешным, пока банк не подтвердил его; необходимы исходные `RRN` и `INT_REF`.

## Проверка стенда

Публичная тестовая карта из документации: `4899939998491778`, срок `04/27`, CVC `917` (Frictionless). Использовать только на тестовом домене банка.

14.10.2026 подписанный запрос открыл страницу банка «Авторизация» с суммой 350 ₸. Подписи покупки, проверки и возврата совпали со всеми тремя контрольными примерами BCC. Проверка `TRTYPE=90` вернула JSON, привязанный к исходному номеру и сумме.

На дату проверки публичный CGI-стенд отклоняет POST текстом `This script can only be used to decode form results`. Для открытия тестовой страницы и серверной проверки используется GET; для live сохранён POST. Собственная форма BCC после ввода тестовой карты также возвращает этот текст. Поэтому успешное списание на стенде пока не подтверждено. Банковская проверка показывает `ACTION=3, RC=-40` — обработка формы продолжается, это не успешная оплата и не окончательный отказ.

Для обращения в BCC достаточно указать тестовый терминал `88888881`, адрес `https://test3ds.bcc.kz:5445/cgi-bin/cgi_link`, дату, ошибку CGI при POST, а также то, что GET и `TRTYPE=90` работают. Реальные ключи и карты в обращение не включать.
