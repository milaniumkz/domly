# Перевод и оформление заказчика — 23.10.2026

- Каталог `backend/src/localization/kazakh.json` содержит 3617 казахских переводов. `python3 scripts/generate_kazakh_catalog.py` обновляет встроенный Dart-словарь и SQL seed. На устройстве не вызываются внешние сервисы перевода.
- SQL seed заполняет пустые переводы, названия и описания каталога; существующие непустые редакторские переводы сохраняются. Выполняется штатным entrypoint под миграционной блокировкой после схемы.
- Переводятся общие подписи, валидация, ошибки API, названия пакетов, уведомления и push по языку получателя. Шаблоны сохраняют значения параметров. Пользовательская переписка и имена автоматически не переводятся; текст, нарисованный внутри растрового баннера, не является текстом интерфейса.
- Переносы строк юридических документов сохраняются. Оферта и политика используют общий компонент: заголовок каждого пункта отдельно, текст ниже, отступ между пунктами. Содержимое документов не изменяется.
- Учебный заказ показывает текущий день и следующие два календарных дня, включая переход месяца/года и високосный февраль. Не создаёт реальный заказ/счёт.
- Баннеры главной заполняют всю карточку с `BoxFit.cover`; изображение не растягивается с искажением пропорций, возможна обрезка краёв по соотношению сторон.
- Астана обслуживается целиком: сохранённый адрес не требует старого `houseId` для покупки пакета. Сервер сообщает покрытие адреса; поиск точного UUID не зависит от первой страницы справочника. Для других городов сохраняется действующий сценарий подключения.
- Фоновые опросы последовательно обновляют данные, отбрасывают одинаковые снимки и сохраняют последний успешный экран при временной ошибке. Первоначальная ошибка по-прежнему показывается. Реальные изменения и восстановление сети доставляются в поток; смена языка/словаря обновляет интерфейс только при изменении.

Проверки: backend с реальной тестовой PostgreSQL; Flutter localization/models/services/utils/app; тесты абзацев RU/KK, параметров переводов, языка push, календарных переходов, городского покрытия, повторных опросов/ошибок/отмены и точного поиска адреса за пределами первой страницы. Production-данные для тестов не создаются.

## Тёмная тема

`DomlyPalette` задаёт фон, поверхность карточки, текст и границы для явных цветов экранов заказчика/Pro и общих компонентов. Экраны подписаны на изменение Theme; незакрытая страница обновляет цвета сразу, сохраняя состояние формы. Material dialogs, bottom sheets и поля ввода используют соответствующую тёмную палитру. Светлая тема сохраняет исходные цвета, акценты и изображения. Проверки покрывают переключение реальной карточки, прозрачность и контраст текста относительно фона и карточек.

История платежей показывает все записи `/payments/my`, включая `rejected`, `pending`, `refunded` и неизвестные будущие статусы; серверный отказ больше не скрывает платёж. Мобильный заголовок исправлен на «История платежей».

Поиск ЖК сохраняет название комплекса отдельно от улицы/дома в `customer_addresses.residential_complex`. Результат подсказки содержит конкретный дом, поэтому выбор по ЖК и повторное сохранение не подменяют улицу названием комплекса. Название и адрес показываются вместе; разные дома одного ЖК остаются отдельными вариантами.

OTP Green API: перед `sendMessage` проверяется `getStateInstance`. Состояние, отличное от `authorized`, недоступный ответ или таймаут считаются ошибкой канала, а не успешной отправкой: сообщение не ставится в очередь, действует существующий failure-only показ кода. При авторизованном канале и успешном приёме сообщения код на экране скрыт. Принятие сообщения провайдером само по себе не является подтверждением доставки на телефон. Потерянную авторизацию инстанса восстанавливает владелец WhatsApp через QR/связанные устройства.

Главная: покупка пакета и заказ без выбранной даты не считаются ближайшей запланированной уборкой. Отсутствующая дата не превращается в служебное «1 января». Дата/подпись и статус располагаются друг под другом без обрезки, в том числе при увеличенном тексте. Экран площади показывает «На проверке» только при отправленном документе; карточка техплана имеет высоту по содержимому, поток профиля сохраняется при редактировании формы.
