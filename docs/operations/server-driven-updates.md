# Изменения без новой мобильной сборки

Поддерживаемый путь: администратор сохраняет данные на сервере, приложение получает их через существующие API. Не загружать исполняемый Dart/JavaScript-код вместо обновления приложения и не менять контракты старых версий.

| Что менять | Где | Доставка |
|---|---|---|
| Фразы интерфейса RU/KK и шаблоны с параметрами | «Тексты и переводы» | `/translations`; обновление словаря каждые 30 секунд; стандартные фразы остаются при ошибке загрузки |
| Полная оферта, политика, информационные страницы | Редактор информационных страниц | `/content-pages/:slug`; полные тексты и отдельные переводы, безопасная прокрутка |
| Пакеты, дополнительные услуги, баннеры, акции | Соответствующие разделы админки | Каталог и `/app/bootstrap`; финансовые значения меняет только уполномоченный администратор |
| Существующие параметры формы «Настройки» | «Настройки» → «Редактировать политики» | `/admin/settings`; сохраняется карта настроек, документы не затрагиваются |
| Серверные статусы, проверки, интеграции | Проверенный релиз backend | Сохраняются совместимость API, аутентификация и идемпотентность |

Существующие экраны получают поддерживаемые значения с сервера. Произвольный новый ключ настройки сам по себе не добавляет поведение: его обязан поддерживать клиент или сервер. Новые экраны, нативные разрешения, камеры/SDK, неподдерживаемые виды компонентов и изменения локальной логики требуют сборки приложения.

Управление всеми жёстко заданными серверными push-фразами и всеми элементами UI ещё не централизовано. Нельзя считать любую запись в runtime metadata работающей функцией без проверки её потребителя. Расширять конфигурацию следует добавлением необязательных полей с прежними значениями по умолчанию, тестом старого клиента и повтором пользовательского сценария. При ошибке загрузки сохраняются последние доступные данные либо штатные значения; обновление не должно сбрасывать текущую форму или повторять платежи.

Тест не запускается на production и не меняет реальные тарифы/бонусные правила.
