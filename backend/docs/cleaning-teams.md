# Командные уборки

Для новых заказов площадью более 250 м² сервер подбирает команду: минимум `ceil(площадь / 250)` клинеров. Для уборки после ремонта состав увеличивается также по времени: сохраняется 25 человеко-минут на м², а длительность визита равна округлённой вверх общей трудоёмкости, делённой на число участников.

Каждый участник должен иметь утверждённый график, свободный общий интервал и остаток дневного лимита площади. Норма — 220 м², предельный дневной лимит — 250 м², включая выполненные уборки. Завершение разрешено максимум через два часа после конца смены. Начало для клиента остаётся в диапазоне 08:00–18:00; для ремонта сохраняется заблаговременность 24 часа.

Вся команда резервируется одной транзакцией оформления. Конкурирующие оформления и назначения используют общий advisory lock; частичный подбор не создаёт заказ и не списывает визит. Пакет теряет ровно одну уборку. Цена для клиента не умножается на число участников. Сумма, используемая существующим расчётом вознаграждения, распределяется поровну в `cleaner_order_workloads`; остаток тиынов распределяется по номерам мест, сумма долей точно равна исходной.

Каждый клинер принимает предложение отдельно. Родительский заказ становится `assigned` после принятия всей командой. Отказ или истечение предложения освобождает только соответствующее место. Принятые участники сохраняются. Замена продолжается автоматически; при отсутствии подходящего клинера заказ остаётся в поиске. Администратор может заменить конкретное место через `POST /admin/orders/:id/assign-cleaner` с `cleanerId` и `teamSlot` (нумерация с нуля).

Начало подтверждает клиент. У каждого участника свой чек-лист, фотоотчёт и отметка завершения; весь заказ завершается после последнего участника. Оценка клиентом команды сохраняется каждому исполнителю; клинеры оценивают клиента независимо.

## Совместимость API

Ответ доступного времени дополнен `requiredCleaners`, `laborDurationMinutes`; `durationMinutes` и `endTime` отражают параллельную длительность. Пустой массив означает отсутствие полной подходящей команды. Сервер повторяет проверку при создании заказа.

Заказ содержит `required_cleaners`, `labor_duration_minutes`, а списки и административные детали — `team_members`. Для установленного Pro-приложения `/orders` и `/cleaner/orders` возвращают заказ каждому принятому участнику; `cleaner_id`, `area`, `total_amount` и собственный `status` персонализированы, исходные `primary_cleaner_id`, `service_area`, `team_order_status` сохранены отдельно. Это позволяет работать с существующими маршрутами начала, отчётов и завершения. Нужные права повторно проверяются на сервере.

Старая схема одиночных заказов не изменяется. Добавлены таблицы участников и командных фотоотчётов, новые поля заказа и представление нагрузки; ранее оформленные одиночные назначения сохраняются. В web-календаре недоступные дни отключаются, выбранные допуслуги участвуют в пересчёте дат. Для такого поведения календаря в установленном мобильном приложении потребуется клиентская сборка; серверное бронирование и отображение участникам поддерживают прежние маршруты API.
