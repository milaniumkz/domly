# MooonAI, Kaspi Pay и чат DOMLY

Firebase используется только для FCM. Счета, сообщения, статусы и задания на напоминания хранятся в PostgreSQL. Миграция добавляется через `sql/schema.sql`.

## Настройки сервера

`MOON_AI_ENABLED=true`, `MOON_AI_CHANNEL_URL=https://core.mooonai.com/api/v1/channels/api/messages`, `MOON_AI_CHANNEL_API_KEY` (отдельный ключ API-канала), `MOON_AI_WEBHOOK_TOKEN` (секрет обратных вызовов), `MOON_AI_SOURCE=domly`. Общий ключ организации не требуется приложению или серверу. Не помещать ключи в Flutter, git или логи.

Workflow `Configure Moon AI` переносит настройки в зашифрованном RSA-OAEP/AES-GCM конверте. Сначала `prepare` генерирует одноразовый публичный ключ, затем `apply` принимает только зашифрованный JSON. Старый backend.env сохраняется в закрытом backup, остальные переменные сохраняются. `inspect` выводит только наличие настроек.

## Выставление и подтверждение счёта

После выбора Kaspi и ввода номера backend берёт сумму из своего платежа и ставит запрос в отдельную очередь `moon-ai`. API-канал получает `thread_id=ID задания очереди`, `source=domly_invoice`. Личный чат использует `thread_id=chatId`, `source=domly`.

В MooonAI нужны активные функции:

- `create_order`: интеграция Kaspi Pay `create_payment`, параметры `phone_number`, `payment_sum`. Одно выставление на платеж; после результата вызывается `set_info`.
- `set_info`: POST `https://domly.kz/api/v1/payments/moon-ai/kaspi-status`, заголовок `X-MoonAI-Token`, JSON **только** `phone`, `amount`, `status`, `dateTime` (ID платежа не нужен). Статусы: `invoice_sent`, `paid`, `rejected`, `cancelled`. Реакции Kaspi Pay на фактическую оплату/отмену вызывают эту функцию.

Backend сопоставляет сумму, нормализованный телефон и исходное время события с ожидающим счётом. Все четыре поля обязательны. `dateTime` — ISO 8601 с часовым поясом и реальным временем события; при повторе не подменять текущим временем. `invoice_sent` сопоставляется с запросом за последние 20 минут, остальные события — с запросом за последние 72 часа. Учитываются и уже обработанные счета, чтобы не принять повтор оплаты за новый платёж. Событие, предшествующее запросу счёта, не подтверждает новый счёт.

Если совпадение единственное — статус применяется автоматически: `invoice_sent` означает выставленный счёт, `paid` активирует покупку, `rejected` — отказ/ошибка, `cancelled` — отмена/истечение. Если совпадений нет или их несколько — событие записывается в `moon_ai_payment_callbacks`, администратору отправляется уведомление, спорные платежи помечаются «Нужна ручная проверка»; автоматического одобрения нет. Повтор идентичного события распознаётся по SHA-256 нормализованных телефона, суммы, статуса и времени. Уже оплаченный/отменённый/возвращённый платёж сохраняет итоговое состояние. При отсутствии ID невозможно достоверно различить два одновременных счёта с одинаковым телефоном и суммой; это намеренно требует ручной проверки. Неоднозначная сетевая ошибка переводит доставку в `uncertain`; автоматического повторного выставления нет, требуется проверка менеджера.

Заказчик получает персональные уведомления о выставлении счёта, отказе/ошибке и отмене с переходом в историю платежей. Успешная оплата использует существующее уведомление и активацию покупки; дубли уведомлений исключаются ключом события. Позднее событие не отправляет уведомление, противоречащее итоговому состоянию.

Ручное одобрение в админке сохраняется и для ожидающих платежей/ошибок интеграции (`pending`, `invoice_requested`, `rejected`, `failed`). Оплаченные, отменённые и возвращённые платежи не переодобряются. `approval_source`, `approved_by`, `approved_at` записывают первое подтверждение: `manual` или `moon_ai` (также `kaspi`, `bcc`, `bonus`). Повторное событие не заменяет источник. В истории и заявках показаны источник, время и администратор. Старые платежи без достоверной информации помечены «Источник подтверждения не указан».

Текст клиента, ответ бота и скриншот чека не считаются банковским подтверждением. Kaspi Receipt не заменяет подтверждение связанного счёта Kaspi Pay. Возврат во внешнем банке требует отдельной согласованной операции; эта интеграция не обещает автоматический банковский возврат.

## Чат и напоминания

API-канал отправляет события в POST `https://domly.kz/api/v1/integrations/moon-ai/messages` с `X-MoonAI-Token`. Ответы agent/manager сохраняются один раз по `event_id`, только в известном приватном чате. Эхо пользовательских сообщений и служебные сообщения счетов игнорируются. Уведомление получает только владелец чата.

Пользователь открывает чат через «Помощник Domly» в настройках; гость — на экране входа. Приватный ключ гостевой установки хранится отдельно от авторизации, на сервере — только SHA-256. При регистрации гостевой доступ и токены отзываются, история гостя остаётся изолированной. Гость не может перехватить активный FCM-токен аккаунта; при подключении токена к авторизованному аккаунту гостевая привязка удаляется в той же транзакции.

Однократные задания через 30 минут:

- неоплаченный checkout: помощь с оформлением; отменяется после оплаты/отмены и при новом checkout;
- новая регистрация без оформления и сообщений: приветствие;
- первый запуск без регистрации и сообщений: приветствие гостю.

Само скачивание без запуска приложения не наблюдаемо. Сообщение останется в чате; push возможен только с разрешением пользователя и зарегистрированным FCM-токеном. Задание проверяет актуальное состояние перед отправкой. Рабочая очередь запускается каждые 10 секунд, приложение читает чат каждые 2 секунды.

## Проверка

`npm test` с `DOMLY_INTEGRATION_DATABASE_URL` проверяет реальную PostgreSQL: дедупликацию счета, проверку суммы/номера, источник ручного/автоматического одобрения, изоляцию чатов, отзыв гостевой сессии, 30-минутные задания и отсутствие повторного счета при таймауте. Flutter `flutter test` проверяет маршруты, гостевые сессии и подписи платежей. Реальное выставление/оплата проверяются только на разрешённой покупателем операции; технический чат сам по себе не подтверждает банковскую оплату.
